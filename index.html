Introduction

Welcome to the Societify documentation. Societify is a comprehensive Multi-Tenant SaaS Platform for Society Management, designed to streamline operations for residential communities, offering seamless management of visitors, billing, facilities, and communications.

📱

Single Mobile App for All Roles

Societify Mobile is a unified Flutter application that supports 9 distinct user roles in a single app: Super Admin, Society Admin, Sub Admin, Accountant, Resident, Guard, Vendor, Staff, and Collector. Users simply log in with their credentials, and the app automatically routes them to their role-specific dashboard.

Platform Architecture

🌐

Societify Web

Laravel 12 + React 19 + Inertia.js

Admin Panel & Backend API for Super Admin, Society Admin, Sub Admin, and Accountant roles.

📱

Societify Mobile

Flutter 3.x with GetX

Single unified mobile app supporting all 9 user roles with role-based dashboards and features.

System Requirements

Before installing Societify, ensure your environment meets the following requirements:

You don't have to check this by hand. The installation wizard at /install tests every item on this page automatically and tells you exactly what is missing before it lets you continue.

Backend Server

  • PHP 8.2 or higher — 8.3 / 8.4 supported and recommended
  • Web server: Apache 2.4+ with mod_rewrite, or Nginx 1.18+
  • Composer 2.0+ (PHP dependency manager)
  • Node.js 18 LTS or higher with npm — only needed if you want to rebuild or customise the frontend; compiled assets ship with the package
  • Memory limit: 256 MB minimum, 512 MB recommended for large societies
  • max_execution_time: 120 seconds or higher, so bulk bill generation does not time out
  • Cron: one entry running Laravel's scheduler every minute (see Cron Jobs)
  • SSL certificate: required in production — the mobile app talks to the backend over HTTPS only

Database Engine

Pick one. MySQL is the usual choice for production; SQLite is fine for evaluating the product or running a single small society.

  • MySQL 5.7+ (8.0 or higher recommended)
  • MariaDB 10.3+
  • PostgreSQL 12+
  • SQLite 3.8+

Required PHP Extensions

The installer will not proceed unless all of these are enabled:

  • pdo — plus the driver for your database: pdo_mysql, pdo_pgsql or pdo_sqlite
  • mbstring
  • openssl
  • tokenizer
  • json
  • curl
  • xml (with libxml, dom and simplexml)
  • fileinfo

Strongly recommended — not blocking, but some features degrade without them:

  • gd or imagick — image processing for uploads and PDF invoices
  • zip — the one-click updater and report exports
  • bcmath — precise financial calculations
  • intl — multi-currency and multi-language formatting

Required PHP Functions

Shared hosts often block these through disable_functions. Because extension_loaded() cannot detect that, the installer checks them separately — an install would otherwise pass the extension check and then fail halfway through.

  • Blocking — installation cannot complete without them: putenv, symlink, file_get_contents, file_put_contents, copy, random_bytes
  • Optional — the app runs fine without them, but database backups and the one-click updater need them: exec, proc_open, set_time_limit

Writable Directories

These must be writable by the web server user — normally 755, or 775 where the web server runs under a different group:

storage
storage/app
storage/framework
storage/logs
bootstrap/cache
Important: Point your domain's document root at the public directory, not the project root. Serving the project root exposes .env and your entire source tree to the internet.

Mobile App Development

Only needed if you intend to build and publish the Android / iOS apps yourself. The complete Flutter source code is included in your download.

  • Flutter SDK 3.x — run flutter doctor until it reports no blocking issues
  • Dart SDK 3.0 or higher
  • Android: Android Studio with Android SDK 34+ and JDK 17
  • iOS: macOS with Xcode 15+ and CocoaPods — iOS builds require a Mac, there is no way around this
  • Firebase project (free tier is fine) for push notifications, plus your own google-services.json / GoogleService-Info.plist
  • Google Play Developer account (one-time fee) and/or Apple Developer Program membership (annual fee) to publish

Installation

Follow these steps to set up the Backend and the Mobile Application.

What's in the download. The package contains two folders: societify-web/ (the Laravel backend and admin dashboard) and societify-app/ (the Flutter mobile app source). Only societify-web/ goes on your server.

1. Web Installer (Recommended)

This is the path almost everyone should take. It needs no terminal access and works on standard shared hosting.

Step 1 — Upload. Extract the download on your computer. Upload the contents of societify-web/ to your server. On cPanel-style hosting this is usually public_html; on a VPS it is typically /var/www/yourdomain.

Step 2 — Point the domain at public. Set your domain's document root to the public directory inside the project. If your host will not let you change the document root, upload the project one level above public_html and make public_html point at the project's public folder.

Step 3 — Install PHP dependencies. The package ships without the vendor folder, so this step is required:

cd /path-to-your-project
composer install --optimize-autoloader --no-dev

No SSH access? Most cPanel hosts expose a "Terminal" or a "PHP Composer" tool under the Software section that runs the same command.

Step 4 — Set folder permissions. Make storage and bootstrap/cache writable (see System Requirements for the full list):

chmod -R 775 storage bootstrap/cache

Step 5 — Create an empty database. Create a database and a database user with full privileges on it, and keep the host, name, username and password to hand. Skip this if you plan to evaluate with SQLite.

Step 6 — Run the wizard. Open https://yourdomain.com/install in a browser and follow the five steps:

  1. Welcome — enter your purchase code to activate the licence.
  2. Requirements — the wizard checks your PHP version, extensions, blocked PHP functions and folder permissions. Anything red must be fixed before you can continue.
  3. Database — enter the credentials from step 5, or choose SQLite. The wizard writes .env and generates the application key for you.
  4. Super Admin — create your own platform owner account. This replaces the demo account.
  5. Finish — migrations and seeders run, and you are redirected to the login screen.
Done. Log in at https://yourdomain.com/super-admin with the account you created in step 4 of the wizard.

2. CLI Installation (Manual)

Use this if you prefer the command line or are automating a deployment.

cd /path-to-your-project

# 1. PHP dependencies
composer install --optimize-autoloader --no-dev

# 2. Environment file and application key
cp .env.example .env
php artisan key:generate

# 3. Edit .env and set your database credentials, APP_URL and APP_ENV=production

# 4. Create the schema and seed demo data
php artisan migrate --seed

# 5. Make uploaded files reachable
php artisan storage:link

# 6. Cache configuration for production
php artisan config:cache
php artisan route:cache
php artisan view:cache
Seeded demo credentials (all passwords are password):
Super Admin — admin@societify.com at /super-admin/login
Society Admin — societyadmin@societify.com at /login
Sub Admin — societysubadmin@societify.com
Accountant — societyaccountant@societify.com
Before going live: change every seeded password, set APP_DEBUG=false and APP_ENV=production in .env, and add the cron entry described in the Cron Jobs section — automated billing, overdue checks and subscription expiry will not run without it.

2. Pointing the App at Your Server

The backend address lives in lib/constants/env_config.dart, which maps three build flavors to three URLs:

dev      → http://10.0.2.2:8000                       (Android emulator loopback)
staging  → https://staging-societify.uniquedeveloper.in
prod     → https://societify.uniquedeveloper.in

You have two ways to point the app at your own backend.

Option A — supply it at build time (recommended). Nothing in the source changes, so future updates never conflict with your edits:

flutter build apk --release \
  --dart-define=FLAVOR=prod \
  --dart-define=BASE_URL=https://yourdomain.com

Option B — edit the defaults. Open lib/constants/env_config.dart and replace the URL returned for Flavor.prod with your own.

Use the bare domain, not the /api path. Pass https://yourdomain.com — the app appends /api to each endpoint itself. Include https://, and no trailing slash.
About SSL certificate pinning. The app ships with a certificate pin for the demo server only. The moment you point baseUrl at your own domain, pinning turns itself off automatically — a stale pin would otherwise break every connection with an unhelpful TLS error. To pin your own certificate, read its fingerprint and pass it at build time: 
openssl s_client -connect yourdomain.com:443 </dev/null \
  | openssl x509 -noout -fingerprint -sha256

flutter build apk --release \
  --dart-define=FLAVOR=prod \
  --dart-define=BASE_URL=https://yourdomain.com \
  --dart-define=PINNED_SHA256=AA:BB:CC:...
Re-issue the build whenever that certificate is renewed, or the app will stop connecting.
Testing locally. Run the backend with php artisan serve and start the app with flutter run --dart-define=FLAVOR=dev. On an Android emulator, 10.0.2.2 is the host machine's localhost. On a physical device, pass your computer's LAN IP with --dart-define=BASE_URL=http://192.168.x.x:8000 instead.

5. Firebase Setup

Push notifications — including the visitor-approval popup — need your own Firebase project. The package ships .example template files; you replace them with the real ones.

  1. Create a free project at console.firebase.google.com.
  2. Add an Android app using the exact package name you set in step 4, then download google-services.json and place it at android/app/google-services.json.
  3. Add an iOS app using your bundle identifier, download GoogleService-Info.plist and place it at ios/Runner/GoogleService-Info.plist.
  4. In the Firebase console open Project settings → Service accounts and generate a new private key. This downloads a JSON file.
  5. Upload that JSON in your web dashboard under Super Admin → Settings → Notifications. This is what lets the backend send push messages.
Important: The package name in Firebase must match your app's package name exactly, and the bundle ID must match your iOS bundle identifier. A mismatch produces an app that builds and runs but silently never receives a notification.
Never commit or redistribute the service-account JSON. It grants full administrative access to your Firebase project. Keep it out of your repository and out of any package you share.

8. Pre-Release Checklist

  • BASE_URL points at your production backend, over HTTPS
  • Your own google-services.json and GoogleService-Info.plist are in place
  • Package name / bundle identifier changed from the default
  • App icons, splash screen and display name replaced with your branding
  • Release signing configured — an unsigned or debug-signed build is rejected by both stores
  • Test on a real device: login, push notification, visitor approval popup, and one payment
Keep your keystore safe. Back up android/app/key.jks and key.properties somewhere secure. If you lose the keystore you can never publish an update to the same Play Store listing — you would have to publish a brand new app and every existing user would need to reinstall.

Cron Jobs

Societify needs one cron entry. Laravel's scheduler handles the rest internally, so you never add a second line no matter how many tasks exist.

* * * * * cd /path-to-your-project && php artisan schedule:run >> /dev/null 2>&1
This is not optional. Without it, monthly bill cycles are never generated, bills are never marked overdue, late fees never accrue, renewal reminders are never sent, and expired subscriptions keep working indefinitely. This is the single most common reason a new installation "stops working" after a few weeks.

Adding it on cPanel

  1. Open Advanced → Cron Jobs.
  2. Under Common Settings choose Once Per Minute (* * * * *).
  3. Paste the command above, replacing /path-to-your-project with your real path (usually /home/username/public_html).
  4. If your host runs several PHP versions, use the absolute PHP binary path instead of bare php — for example /usr/local/bin/ea-php83 artisan schedule:run.

What the scheduler runs

TaskWhenWhat it does
Generate billing cycle1st of each month, 02:00Creates the next billing cycle for every active society
Check overdue billsDailyFlags unpaid bills as overdue so late fees begin accruing
Check subscription expiryDaily, 09:00Flags SaaS subscriptions expiring in 7, 3 and 1 days
Send renewal remindersDaily, 10:00Emails and pushes renewal notices to society admins
Revoke expired accessDailyRevokes API tokens once the 5-day grace period has lapsed
Clear password resetsDailyDeletes expired password-reset tokens

Verifying it works

Run the scheduler by hand once and confirm it reports the tasks it would run:

php artisan schedule:list
php artisan schedule:run

If schedule:run prints "No scheduled commands are ready to run", that is normal — it simply means nothing is due at this exact minute. Errors, on the other hand, will appear in storage/logs/laravel.log.

Super Admin Guide

The Super Admin panel is the central control hub for managing the entire platform. It allows you to oversee multiple societies, manage subscriptions, and configure system-wide settings.

1. Managing Societies

Navigate to the Societies tab to create and manage society accounts. This is where you onboard new communities onto the platform.

  • Create Society: Add new societies with details like name, address, and admin contact.
  • Status Management: Active, suspend, or delete society accounts.
  • View Details: Access society-specific analytics and settings.

2. Subscription Plans

Create various subscription tiers (e.g., Free, Gold, Platinum) with different feature sets and limits. You can define monthly and yearly pricing for each plan.

3. User Management

View and manage all system users, including other admins and society staff. You can reset passwords and update roles directly from this panel.

Society Admin Guide

The Society Admin panel is designed for managing the day-to-day operations of a specific community, covering everything from residents to financial accounting.

1. Property Management

Set up the physical structure of your community by defining buildings (blocks) and individual units (flats/villas).

Buildings

Units

2. Resident Management

Maintain a digital directory of all residents. The system supports Owners, Tenants, and Family Members.

3. Billing & Accounting

Automate your society's finances. The billing module allows you to generate bills, track revenue, and record expenses.

4. Visitor Management

Secure your gates with the visitor tracking system. Guards can check residents in/out, and residents can pre-approve guests via the mobile app.

Manage community amenities like Clubhouses, Swimming Pools, and Tennis Courts. Residents can book slots online, and you can track utilization.

A centralized system for tracking resident complaints. Assign tickets to staff (electricians, plumbers) and track resolution times.

7. Announcements & Notices

Broadcast important information to all residents instantly via mobile push notifications and email.

Late Fees & Penalties

Configured per society under Society Admin → Settings → Billing. Late fees are applied by the daily app:check-overdue-bills scheduled task, so they only accrue if your cron entry is running.

Calculation types

TypeHow it is calculated
Fixed amount per dayA flat sum for each day overdue
Percentage per dayA percentage of the pending amount, for each day overdue
Daily interestAn interest rate applied per day
Monthly interestAn interest rate applied per month overdue, rounded up
Flat penaltyA single charge, applied once

Frequency

  • Daily — accrues incrementally, once per day
  • Monthly — applied once per month overdue
  • One-time — applied once, the first time the bill goes overdue

Grace period

A configurable number of days (0–365) after the due date during which no late fee accrues. Set it to 0 to start charging the day after the due date.

Worked examples

Daily interest, 2% per day, 5 grace days. A ₹10,000 bill due 1 January, viewed on 10 January. Nine days have passed, five are absorbed by the grace period, so four are chargeable: 10,000 × 2% × 4 = ₹800.

Monthly interest, 5% per month, no grace. A ₹10,000 bill due 1 January, viewed on 15 March. Two months overdue (rounded up): 10,000 × 5% × 2 = ₹1,000.

Flat penalty, ₹500, one-time, 7 grace days. A ₹10,000 bill due 1 January, viewed on 10 January. Past the grace window, so the penalty applies — ₹500, once, and it does not grow.

Late fees are part of the amount due. Every outstanding total, payment check and report uses the bill total including late fees, so a bill is only marked paid once the fee is covered too.
Not accruing? Late fees depend on a bill being flagged overdue, which is a daily scheduled task. No cron means no overdue flag and therefore no late fee. See Cron Jobs.

Printable Documents & PDF Export

Bills, resident statements, bank statements and finance reports are rendered server-side as standalone documents. Each opens in its own browser tab containing only the document plus a small toolbar (Print / Download PDF / Export CSV / Close) that disappears as soon as the browser enters print layout — so navigation and dashboard cards never end up on the printed sheet.

Available documents

DocumentWhereFormats
Resident statement / ledgerSociety Admin → LedgersPrint, PDF, CSV
Bank statementSociety Admin → Bank AccountsPrint, PDF, CSV
Finance reportsSociety Admin → ReportsPrint, PDF, Excel (CSV)
Maintenance bill / invoiceSociety Admin → BillsPrint, PDF

Statements accept a date range and always report an opening balance, the movements in the period, and a closing balance, so a filtered statement still reconciles against the account as a whole. CSV exports carry the same opening and closing rows and are written with a UTF-8 byte-order mark, so Excel renders currency symbols and non-Latin text correctly.

Hindi, Arabic and other non-Latin PDFs

Read this if you use Hindi, Arabic, or any non-Latin language. The PDF renderer ships with only the DejaVu font, which has no Devanagari, Arabic, Thai or CJK glyphs. Those languages print perfectly from the browser, because the browser uses your system fonts — but a PDF export will come out as empty boxes until you install a Unicode font.

Installing a font

Drop a TrueType font into storage/fonts on your server:

storage/fonts/document.ttf        # required
storage/fonts/document-bold.ttf   # optional — synthesised if absent

That is the whole procedure. The matching @font-face is emitted automatically — there is no config file to edit and no cache to clear. Noto Sans is the usual choice, or a per-script build such as Noto Sans Devanagari or Noto Sans Arabic.

Keep the font small. The renderer parses the entire font on first use. A per-script Noto of roughly 200 KB is fine; a 20 MB pan-Unicode font can exceed PHP's default memory_limit on that first render and fail. The parsed metrics are cached next to the font, so only the first render pays the cost.

Customising the look

All documents share one template and one stylesheet, so a change applies to both the printed page and the PDF and the two can never drift apart:

  • resources/views/documents/layout.blade.php — letterhead, meta strip, sign-off, footer, toolbar
  • resources/views/documents/styles.blade.php — the single stylesheet every document uses

Put your letterhead, colours and sign-off wording here. Note that the PDF renderer supports neither flexbox nor CSS grid, which is why the shell is built from tables — keep any additions table-based, and confine browser-only styling to @media print or the .screen-only class, which the PDF renderer ignores.

Razorpay webhook authentication (fixed)

OTP in API response (fixed)

  • Policy: OTP is never returned in API responses.
  • Local testing: OTP may be written to logs for development.

Payment secrets exposure (fixed)

  • Client responses: never include payment gateway secret keys.
  • Public keys only: clients receive only what is needed to initialize SDKs.

PayPal SDK (fixed)

Troubleshooting

The problems buyers actually hit, and what fixes them. Work down the list — the first few cover the large majority of support requests.

Installation

"Vite manifest not found"

The compiled frontend is missing from public/build. Either restore that folder from the original download, or rebuild it:

npm install && npm run build

Blank white page after upload

  • Your document root is pointing at the project folder instead of public.
  • composer install was never run, so vendor is missing.
  • Check storage/logs/laravel.log — the real error is almost always recorded there.
  • Temporarily set APP_DEBUG=true to see the error on screen, then set it back to false.

500 error immediately after install

Usually permissions or a stale cache. Run:

chmod -R 775 storage bootstrap/cache
php artisan config:clear
php artisan cache:clear
php artisan view:clear

The installer says an extension or function is missing

Enable it in your hosting control panel (cPanel: Select PHP Version → Extensions) and reload the page. If a function is reported missing rather than an extension, it has been blocked through disable_functions in php.ini — your host has to remove it from that list.

The installer keeps reappearing after a successful install

The install marker under storage/app/private could not be written. Confirm storage is writable and run the wizard again.

404 on every page except the homepage

URL rewriting is off. On Apache, enable mod_rewrite and allow .htaccess overrides (AllowOverride All). On Nginx, add Laravel's try_files $uri $uri/ /index.php?$query_string; to your server block.

Scheduled Tasks & Billing

Bills are not generating automatically

Nine times out of ten the cron entry is missing or wrong. Check the Cron Jobs section, confirm the path is correct, and if your host runs multiple PHP versions use the absolute path to the PHP 8.2+ binary rather than bare php.

Late fees are not being applied

Late fees accrue only after a bill is marked overdue, which is a daily scheduled task. No cron means no overdue flag and therefore no late fee. Also confirm a penalty model and grace period are configured under Society Admin → Billing Configuration.

A custom billing formula is rejected when saving

Formulas accept numbers, + - * /, parentheses and the named variables shown beside the field — nothing else. Function calls and unknown variable names are refused deliberately. The inline error names the offending token.

Mobile App

The app cannot reach the server / login times out

  • Confirm you built with --dart-define=BASE_URL=https://yourdomain.com — without it the app points at the demo server.
  • Use the bare domain, with https:// and no trailing /api.
  • Open https://yourdomain.com/api/locales in a browser. If that returns JSON, the backend is fine and the problem is in the app's configuration.
  • A self-signed or expired SSL certificate will be rejected. Use a valid certificate.

"SSL Certificate Pinning failed"

A pin is set that does not match the certificate actually being served — normally because the certificate was renewed. Either rebuild with the new fingerprint via --dart-define=PINNED_SHA256=..., or omit that flag to disable pinning.

Push notifications never arrive

  • The Firebase package name must match your app's package name exactly — a mismatch fails silently.
  • The service-account JSON must be uploaded under Super Admin → Settings → Notifications.
  • iOS additionally needs an APNs key uploaded to Firebase and the Push Notifications capability enabled in Xcode.
  • Notifications do not work on the iOS Simulator — test on a real device.

The visitor approval popup does not appear

  • It is Android-only. iOS shows a standard notification with Approve / Reject actions instead.
  • The resident must have granted the "Display over other apps" permission — it is offered once at first login and can be re-enabled from Settings → Instant Delivery Popups.
  • Aggressive battery savers on some Android brands kill background delivery. Exclude the app from battery optimisation.

The build fails after changing the package name

The package name must be updated consistently in android/app/build.gradle.kts, the AndroidManifest.xml files and the Kotlin source folder path, and it must match the Firebase configuration. Then run flutter clean && flutter pub get before rebuilding.

Payments

Payments succeed at the gateway but the bill stays unpaid

The webhook is not reaching your server or its secret is wrong. Confirm the webhook URL is registered in the gateway dashboard, that the secret matches the one stored in Settings, and that your server is publicly reachable over HTTPS.

The payment option does not appear in the app

Gateway credentials are stored per society, not in .env. Configure them under Society Admin → Settings → Payment, and make sure the gateway is enabled. The app fetches the enabled list at runtime.

"Too many requests" during testing

Payment and authentication endpoints are rate limited on purpose — 10 payment requests per minute, and stricter limits on login and OTP. Wait a minute and continue.

Email & SMS

Emails are not being delivered

SMTP settings live in the dashboard, not .env. Configure them under Super Admin → Settings → Mail and use the built-in test button. If the test passes but real mail does not arrive, check spam and confirm your sending domain has SPF and DKIM records.

OTP messages are not arriving

Confirm the SMS provider credentials under Super Admin → Settings, that your provider account has balance, and that the phone number includes the correct country code. The settings screen has a test button for SMS and WhatsApp.

Still stuck?

Before requesting support, collect: your PHP version, database engine, the exact error message, and the last 50 lines of storage/logs/laravel.log. That usually turns a multi-day exchange into a single reply.
